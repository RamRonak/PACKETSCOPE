TCP

Transmission Control Protocol

Layer 4 (Transport) • RFC 793, RFC 9293

Connection-Oriented
Purpose & Reliability

TCP provides reliable, ordered, and error-checked delivery of a stream of octets between applications running on hosts communicating via an IP network. It guarantees delivery through sequence numbers, acknowledgments (ACKs), timeouts, and retransmissions.

The 3-Way Handshake
Client ──────── SYN (Seq=x) ───────> Server
Client <──── SYN-ACK (Seq=y, Ack=x+1) ──── Server
Client ──────── ACK (Ack=y+1) ───────> Server

UDP

User Datagram Protocol

Layer 4 (Transport) • RFC 768

Connectionless
Purpose & Philosophy

UDP is a minimalist transport layer protocol that provides a connectionless datagram service without handshakes, sequence tracking, or retransmission. It trades delivery guarantees for maximum throughput and minimal latency.

Typical Use Cases
  • Domain Name System (DNS) queries on port 53.
  • Dynamic Host Configuration (DHCP) discover/offer on ports 67/68.
  • Real-time Voice & Video Streaming (VoIP, WebRTC) where speed beats retransmissions.
  • Network Time Protocol (NTP) on port 123 for clock synchronization.

Example Use Case: DNS resolutions, video calling, live telemetry
PacketScope ID: IP Protocol #17 or UDP layer presence
ICMP

Internet Control Message Protocol

Layer 3 (Network Diagnostic) • RFC 792

Diagnostic / Error
Purpose in Network Defense

ICMP is used by network devices (including routers and hosts) to send error messages and operational information indicating whether a requested service or host is reachable. It does not carry application payload and is essential for utilities like ping and traceroute.

Core ICMP Types & Codes

Example Use Case: Ping connectivity, Traceroute path discovery
PacketScope ID: IP Protocol #1 or ICMP layer presence
DNS

Domain Name System

Layer 7 (Application) • RFC 1034, RFC 1035

Port 53 (UDP/TCP)
How Resolution Works

DNS acts as the phonebook of the Internet, translating human-friendly names (e.g., packetscope.local) into numerical IP addresses (e.g., 142.250.190.46). Clients issue recursive queries to resolvers, which traverse the root, TLD, and authoritative nameservers.

HTTP / HTTPS

Hypertext Transfer Protocol (Secure)

Layer 7 (Application) • RFC 2616, RFC 7230, RFC 8446

Ports 80 & 443
HTTP (Cleartext Transport)

HTTP is an unencrypted request-response protocol. Requests feature ASCII verbs (GET, POST, HEAD), URI paths, and headers. Responses return status codes like 200 OK, 404 Not Found, or 500 Internal Error. PacketScope safely sanitizes authorization tokens and passwords in cleartext payloads.

HTTPS (TLS/SSL Encrypted)

HTTPS runs HTTP over a Transport Layer Security (TLS) tunnel. The client and server perform a cryptographic handshake to authenticate via X.509 certificates and negotiate symmetric session keys. PacketScope ethical policy: Never attempts to decrypt or tamper with TLS traffic.

Ports: 80, 8080 (HTTP) • 443, 8443 (HTTPS)
Example Use Case: REST APIs, web apps, cloud services
PacketScope ID: HTTP header signatures or port matching
ARP

Address Resolution Protocol

Layer 2/3 (Link to Network Translation) • RFC 826

EtherType 0x0806

ARP bridges the gap between Layer 3 logical IP addresses and Layer 2 physical hardware MAC addresses on a local broadcast domain. When Host A wishes to send a packet to Host B on the same LAN, it broadcasts an ARP Request: "Who has IP 192.168.1.1? Tell 192.168.1.100." Host B unicasts an ARP Reply: "192.168.1.1 is at aa:bb:cc:dd:ee:ff."

Scope: Local broadcast domain (not routable across Internet)
Example Use Case: LAN default gateway resolution
PacketScope ID: Ethernet EtherType 0x0806 or ARP opcode
